# Как работать над проектом

## Один раз после клонирования
1. Запусти tools\hooks\install.bat. Это хуки, которые сами решают конфликты в картах (.dmm) и иконках (.dmi).
2. Убедись, что проект собирается: Ctrl+F7 в DM IDE (или tools\build\build.bat).

## Правила
- В main напрямую не пушим. Всё идёт через Pull Request.
- Одна задача = одна ветка = один небольшой PR. Ветка живёт день-два.
- Название ветки: feature/что-делаем, fix/что-чиним, chore/прочее.
- В локальный main ничего не коммитим, только обновляем его.
- Перед тем как взять общий файл (например _job.dm, vanderlin.dme), напиши в чат.
- Не форматируем и не переименовываем чужие файлы без согласования.
- Не коммитим .dmb, .rsc, собранные бандлы TGUI, node_modules.
- Сливаем PR кнопкой Squash and merge, потом удаляем ветку.

## Рабочий цикл (команды по порядку)
    git switch main
    git pull --ff-only
    git switch -c feature/название

    git add -A
    git commit -m "Что сделано"

    git fetch origin
    git rebase origin/main
    git push -u origin feature/название

Дальше: Pull Request на GitHub, второй человек смотрит, Squash and merge.
После слияния:

    git switch main
    git pull --ff-only
    git branch -d feature/название

## Конфликты
- git status покажет конфликтные файлы. Открой их, убери маркеры <<<<<<<, =======, >>>>>>>.
- Самый частый случай: vanderlin.dme, когда оба добавили #include рядом. Оставь обе строки.
- Затем git add <файл> и git rebase --continue. Если запутался: git rebase --abort.
- Никогда не делай git push --force в main и в чужие ветки.

## Перед деплоем
- main должен компилироваться. Деплой запускаем только после слияния PR.

## Настройка окружения

Делается один раз.

1. Установи Git и VS Code.
2. Установи BYOND ровно той версии, что указана в `dependencies.sh` (сейчас 516.1661):
   https://www.byond.com/download/build/516/516.1661_byond.exe
3. Клонируй репозиторий и открой папку в VS Code:

        git clone https://github.com/ghostezlarin/NewDawn.git
        cd NewDawn
        code .

4. VS Code предложит поставить рекомендованные расширения (DM language client, EditorConfig, DMI editor, Prettier, Biome). Соглашайся.
5. Один раз запусти установку merge-хуков для карт и иконок:

        tools\hooks\install.bat

## Локальный запуск и проверка

Каждый тестирует свои правки на своём компьютере, на боевой сервер для этого выкладывать ничего не нужно.

- **F5** (Run and Debug) и конфигурация **Launch DreamSeeker**: собирает DM и TGUI и открывает клиент игры.
- Если ПК слабый или хочется быстрее, используй **Launch DreamSeeker (low memory mode) no dungeons**.
- **Ctrl+Shift+B** запускает только сборку без запуска игры. Так можно проверить, что код компилируется.
- Первая сборка долгая: она скачивает нужные инструменты и собирает TGUI. Следующие быстрее.
- Если сборка не находит BYOND, укажи путь к установке в настройке VS Code `dreammaker.byondPath`.

## Концы строк

Файлы `.dm` и `.dmm` хранятся с CRLF (см. `.editorconfig`). Расширение EditorConfig в VS Code делает это само. Не меняй окончания строк вручную и не пересохраняй файлы другими редакторами, иначе в PR появится diff на весь файл.

## Перед отправкой PR

1. Сборка проходит без ошибок.
2. Изменение проверено в игре на локальном сервере.
3. В PR описано, что изменено и как это проверить.
